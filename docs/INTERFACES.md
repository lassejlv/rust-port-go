# Bootstrap interfaces

Module: github.com/lassejlv/rust-port-go. All work stays on main. Agents edit their assigned files; the coordinator commits and synchronizes checkpoints.

`internal/syntax.Parse(source string) (*Program, error)` parses the AST in `ast.go`. Errors identify line and column. Function return types default to `()`. Supported type spellings: i32, i64, bool, &str and (). Expression literals keep numeric spelling and decoded string text. Unary operands use Right; conditional expressions use Left as condition and Body/Else for branch blocks. No-semicolon expression statements store Type="()" as their expected type. No implicit externals or ignored unsupported syntax.

`internal/compiler.Check(source string) error` parses and type checks a complete binary crate. `internal/compiler.EmitC(source string) (string, error)` checks and lowers to portable C11. `internal/compiler.Build(sourcePath, outputPath string) error` reads Rust source, emits C to a temporary file and invokes system cc. Compilation never invokes rustc or cargo. Generated executables use libc. Build emits an executable at outputPath.

Cargo package: `internal/cargo.Run(args []string, stdin io.Reader, stdout, stderr io.Writer) int`. CLI entrypoint `cmd/ferrugo-cargo`. Support new/init/build/run/check/clean/version/help for a single binary package with no dependencies. Calls compiler.Build/Check directly. Parse Cargo.toml with an explicitly bounded parser and reject dependencies, build scripts, workspaces and unsupported targets rather than ignoring them. No shell interpolation. CLI errors exit nonzero; child exit status preserved. README is coordinator-owned; cargo agent can write docs/CARGO.md and package tests.

Compiler CLI entrypoint `cmd/ferrugo`, owned by coordinator. Codegen supports lexical scopes, let/mut, assignments, integer arithmetic, booleans, functions/recursion, if/else, while, return/break/continue, println!/print!/assert! (bounded formats), value-producing if/block expressions, unit expressions and function tails. Unsupported Rust constructs must fail clearly. An initial implementation is a bootstrap subset, never full Rust compatibility.

## Next milestone: modules

Syntax additions: `Program.Modules []*Module`, `Program.Imports []Import`; `Module{Name string; Public,External bool; Program *Program; Span Span}`; `Import{Path,Alias string; Public bool; Span Span}`; `Function.Public bool`; `Span.File string`. Parsing supports inline/external module declarations, public fn/mod items, simple use paths and aliases, and qualified call/name paths with crate/self/super. Explicit public reexports, glob/group imports and restricted visibility may initially reject. Existing AST fields stay compatible.

Compiler additions: `analyzeProgram(*syntax.Program) (*checked,error)` accepts parsed/loaded syntax; `resolveModules(*syntax.Program) (*syntax.Program,error)` resolves module paths/imports/privacy and returns a flattened function program using canonical qualified function names. `analyze(source)` parses then calls analyzeProgram; analyzeProgram resolves before existing type checking. Name resolution preserves lexical variable/function shadowing and rewrites only qualified variable-free calls; spans retain source filenames.

File API: `CheckFile(sourcePath string) error`, `EmitCFile(sourcePath string) (string,error)` load external modules using Rust's name.rs/name/mod.rs rules, validate duplicate/missing/ambiguous/cyclic files, stamp filenames, then analyzeProgram. Source-string Check/EmitC support inline modules and reject unresolvable external declarations. Build, compiler CLI and Cargo check use file APIs. The C emitter gets a checked flattened program and needs no module-specific code generation.

## Named-structure milestone

Scope: brace-style named structures with `#[derive(Copy, Clone)]`, primitive/nested Copy fields, struct literals, field reads, field assignments rooted in mutable locals, and struct values as function parameters/results. Requiring Copy keeps this milestone explicit while general moves/borrowing remain unimplemented. Plain/move-only structs, tuple/unit structs, struct update, methods, trait APIs and generic structs stay unsupported. &str fields require lifetime syntax outside this milestone and must reject.

AST: Program.Structs []*Struct; Struct{Name string; Public,Copy bool; Fields []StructField; Span}; StructField{Name,Type string; Public bool; Span}; Expr.Fields []FieldValue, FieldValue{Name string; Value *Expr; Span}; Kind struct uses Text type path, Target canonical type key, Fields; Kind field uses Left receiver and Text field name. Stmt.Target *Expr holds field assignment place; existing Name handles simple variable assignments. Parser accepts named type paths and marks declarations with Copy only for the supported Copy+Clone derive pair.

Resolver: flattened Struct.Name is canonical `module::Name`; type references use `struct:<canonical>`. Program.Structs flattened along with Functions. Imports may alias struct types; privacy applies to type paths. Resolve function params/results, struct fields and let annotations. Preserve source spelling in Expr.Text; struct literal Expr.Target holds its `struct:` type key. Reject unsupported shared item namespace names explicitly. Resolver owns resolve.go/resolve_test.go; type checker owns check.go/check_test.go and new struct_check.go/tests; syntax owns syntax files; coordinator owns C backend/file loader.

Checked representation additions: structs map[string]*syntax.Struct keyed by `struct:` type key; structOrder []string in topological by-value layout order. Type checker rejects missing/unknown/duplicate fields, wrong types, private field accesses/construction, mutable-place violations, recursive by-value layouts and invalid Copy fields. Field operations and constructor expressions populate checked.types as usual; name roots of assignment targets populate checked.names. Struct types cannot use arithmetic/comparison/formatting without separately implemented traits. Type checker checks private return types used outside their defining visibility.

Codegen cType recognizes struct type keys and uses collision-free `fr_struct_` plus hexadecimal UTF-8 canonical-name bytes. Field names are `fr_field_` plus ASCII source identifier. Emit typedef forward declarations and definitions in checked.structOrder before function prototypes. Empty record structs use an inaccessible dummy byte because standard C11 has no empty structs; no layout/ABI introspection is exposed. Constructor fields evaluate in source order, independently of declaration order. Assignment RHS evaluates before a mutable local field place is written.

## Local library/path-dependency milestone

Scope: binary packages compile/link local library-only path dependencies (including transitive/renamed dependencies) into the bootstrap C executable; library packages can be checked. No registry/git/version/feature resolution, workspaces, build scripts or Rust rlib/ABI artifacts. Library-only build/run must reject clearly until a compatible artifact strategy exists. `new/init --lib` may create a minimal supported library template.

Compiler public graph API: `type Crate struct {Root,Identity string; Dependencies map[string]*Crate}` where Root is a Rust crate root file and dependency keys are already-valid Rust extern identifiers. Shared pointers identify the same library crate; optional Identity distinguishes different packages that share one physical source. Cargo supplies the canonical manifest-context identity. Graph loading otherwise interns canonical root paths and rejects inconsistent logical module bases/dependency graphs. `CheckCrate(root *Crate, library bool) error` checks all crates, `BuildCrate(root *Crate, outputPath string) error` builds a binary graph. Existing CheckFile/Build remain binary wrappers with no deps; CheckLibraryFile adds library checking. Coordinator owns new package.go, loader/build/codegen and CLI.

AST graph metadata: Program.Externs map[string]*Program and CrateID string; empty CrateID is root, dependencies get inaccessible canonical prefixes @crate1, @crate2, etc. Each crate has a separate root scope with parent nil, its own extern prelude, and its own crate/self/super semantics. Module resolver agent owns resolve.go/tests and collects each external Program once, preserving shared library type identity; extern aliases resolve only as first unprefixed path segments when no local item shadows them. `crate::dependency`/`self::dependency` do not access the extern prelude. Canonical public/private fields/types continue to use the crate prefix. Root imported-main wrapper remains binary-root-only.

Checker agent owns check.go/tests and adds `analyzeProgramMode(program, requireMain bool)`; existing analyzeProgram delegates requireMain=true. Dependencies may have no main; only the selected binary root needs main. All flattened functions/records type check together. No generator changes except library checks skip native output; BuildCrate remains binary emission.

Cargo agent owns internal/cargo manifest/graph/commands/tests. Bounded `[dependencies]` inline tables accept path and optional package rename only; registry versions/features/git etc reject. Manifest determines one binary root or one library root, rejects dual/multiple targets and build scripts. Build canonical manifest graph with interned packages, dependency alias normalization (- to _), duplicate alias/name validation, package-name agreement and cycle/missing-path errors. Pass compiler.Crate graph directly. `check` supports either root kind; `run/build` require binary root and may use library-only deps. No fake rlib files are emitted.

## Integer/bit-operation milestone

Support signed i8/i16/i32/i64/isize and unsigned u8/u16/u32/u64/usize on the host C target; i128/u128 and cross-target selection remain unsupported. Preserve Rust debug overflow/division/shift checks in both existing profiles. Add integer bitwise !/&/|/^ and shifts << >> plus their compound assignments; boolean &/|/^ evaluate both operands. Shift RHS may have any supported integer type, independently of LHS; invalid negative/out-of-range counts exit 101. Signed right shift sign-extends, and left shift discards shifted-out bits rather than checking arithmetic overflow.

Checker owns integer.go metadata: `type intSpec struct {Bits int; Signed bool; CType,PrintMacro string}` and `integerInfo(name string)(intSpec,bool)`, plus parseInteger/integer typing changes in check.go, unsigned literal bounds and operator/type checks. `checked.assignTypes map[*syntax.Stmt]string` records LHS type for every simple/field assignment (shift RHS type can differ). isize/usize Bits uses host strconv.IntSize; cross compilation unsupported. supportedType and integerType recognize the metadata set. Numeric aliases remain distinct Rust types even at equal width.

Syntax owns integer suffix validation, longest-match shift/compound tokens, standard Rust bitwise/shift precedence and unary binding. AST operator strings remain literal spellings. Named type parsing already accepts the new integer names; coordinator updates resolver primitive fast path to integerType.

Runtime agent owns runtime.go C helpers fr_{add,sub,mul,div,rem,neg}_TYPE, no neg for unsigned, and fr_{shl,shr}_TYPE(T value,uint64_t count). Signed helpers use checked arithmetic; unsigned helpers check against UINTN_MAX. Shift helpers operate through uint64_t unsigned bits, narrow to exact unsigned width, memcpy to signed results and fill sign bits explicitly on right shifts; no undefined C signed shifts or overflow. Coordinator owns codegen cType/literal/format/operator lowering and uses assignTypes for compound targets.

## Integer cast milestone

Add `as` casts between all supported integer types and from bool to a supported integer. Narrowing/sign changes use Rust truncation/sign-extension semantics with no overflow panic. General coercion casts, floats/chars/references/enum casts and `_` targets remain outside this milestone.

AST Expr.Kind="cast": Left operand, Text original target type path, Target resolved target type key. Syntax gives `as` binding above multiplication and below unary, left-associative chains; preserve actual Rust cast/less-than/left-shift parsing restrictions (use rustc oracle). Resolver sets Target through resolveType and keeps source spelling; loader already stamps Left/span.

Checker validates target is integer and source is integer or bool (no numeric-to-bool), records target result type/hint and operand divergence without inventing never-type coercions. It may retain documented local/default inference limits for unsuffixed cast operands. Coordinator owns backend: evaluate operand once, convert to uint64 bits, narrow to unsigned destination type and memcpy into signed destinations. This preserves defined C behavior for unsigned maxima, negative values and narrowing. Unary/compound/expression evaluation order remains unchanged. No runtime trap is introduced by a supported cast.

## Fixed-size Copy array milestone

Scope: `[T; N]` types, `[a,b,...]` and `[value; N]` values, owned Copy-array values in locals/records/functions, usize indexing, mutable place assignment and `.len()`. Elements are supported integers/bool/Copy records/nested arrays; unit/reference/string elements and slices/borrows/iterators remain unsupported. Lengths are unsuffixed/usize integer literals only, normalized to decimal and bounded to 65536; general const evaluation is not implemented. Repeat operands evaluate once even for zero length. All dynamic indexes check bounds and panic101.

AST kinds: array uses Args elements; repeat uses Left value and Text literal count; index uses Left receiver/Right index; len uses Left receiver (array only, no arguments). Stmt assign Target accepts index/field projections rooted in mutable locals. Source type spelling is `[element;length]`; resolver normalizes to `array:<decimalLength>:<canonicalElement>` recursively. No new AST fields.

Checker owns array.go: `type arraySpec struct {Element string; Length int}`, pure `arrayInfo(string)(arraySpec,bool)`, `arrayType(element string,length int) string`, `parseArrayLength(text string,span syntax.Span)(int,error)`; checked.arrays map[string]arraySpec, checked.typeOrder []string and checked.zeroSized map[string]bool. Register canonical arrays from declarations/literals, validate Copy element types and lengths. Layout DFS must include both arrays and records and reject cycles; retain structOrder for existing record-only callers, typeOrder is the complete C-definition order. Move layout completion after function checking so inferred array types are included. Visibility recurses through array elements; public records' private fields remain opaque. Index expects usize, length returns usize; no implicit conversion from other integer types. Extend fixedCastSource/hint/provenance for operator results carefully against rustc.

Coordinator backend: array wrappers use collision-free `fr_array_`+hex canonical key, with typed `fr_data[N]` storage for nonzero-sized arrays. Logical zero-sized arrays/records use one inaccessible initialized byte because C11 lacks zero-sized objects; zero-sized record fields are omitted. Constructors still evaluate every required operand; indexing preserves bounds/effects and produces a zero-value temporary/place when the element has no data. Emit all array/record typedefs and definitions in checked.typeOrder. Constructors initialize then fill in source order; repeats evaluate once then assign copies in a C loop. C layout/ABI remains unexposed.

Index reads MUST preserve Rust place semantics: `a[{a[0]=9;0}]` reads the newly written value, whereas `{a}[{a[0]=9;0}]` reads the earlier temporary copy. For name/field/index place receivers use g.place without copying before the index side effects; rvalue receivers are evaluated into temporaries first. Assignment evaluates RHS before the entire place/index chain; indices within a place evaluate left to right once. g.place must handle divergent indices without emitting malformed C. Bounds checks precede access, including zero-length receivers. len evaluates receiver side effects/bounds even though its result is a known length. Place receivers are borrowed through g.place for len and field projections, avoiding whole-aggregate copies.

## Builtin for-loop milestone

Support `for name in start..end {}` and inclusive `..=`, plus owned Copy-array iteration; `mut name` and wildcard `_` patterns supported. Bounds evaluate left-to-right once, iterable arrays snapshot once before body, pattern binding is new each iteration (immutable unless mut), nested break/continue retain nearest-loop behavior. Open ranges, stored range values, borrowed arrays/slices, general IntoIterator/Step traits, patterns and labels remain unsupported.

AST: Stmt.Kind="for", Name/Mutable/Expr/Body; Expr is either normal array expression or Kind="range" with Left start, Right end and Op .. / ..=. Parser recognizes direct ranges only in for headers; suppress bare struct literals there like while conditions while preserving grouped/array literal constructors. No AST field additions. Range lexer tokens longest-first.

Checker owns for_check.go and check integration: checked.forTypes map[*Stmt]string gives item type; checked.decls[stmt] gives unique pattern binding C name. Bounds must have one supported integer type (use fixed endpoint hints), arrays item type is their Copy element. Check iterable before introducing pattern binding; bind in loop body scope, enforce mutability, underscore inaccessible as expression. Range pseudo-expression may record type metadata but generic value expressions reject it. Loops can execute zero times and therefore do not guarantee a return. A for statement retains unit static typing even when its header diverges; preserve header divergence for lowering but do not let it satisfy a nonunit function result. Verify global inference/cast interactions against rustc: unfixed numeric pattern bindings may need the existing explicit annotation/suffix boundary, while typed bounds/array sources remain supported.

Coordinator C backend: private numeric cursor independent of mutable pattern variable. Exclusive loop increments only while cursor<end, so no overflow. Inclusive loop maintains a finished flag and skips increment at end, including maximum integer endpoints; continue executes this update, break skips it. Array iteration uses the captured owned array and usize cursor; zero-sized elements bind initialized dummy values with all body effects preserved. Length-zero iterable still evaluates once but emits no body loop. No user code runs inside compiler-generated array copy loops, preserving loop-control scopes.
